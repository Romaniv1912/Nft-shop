# NFT Shop — демо-адмінка для Getgems FixPrice Sale v4r1

Проста адмінка, яка показує весь функціонал контракту
[`nft-fixprice-sale-v4r1.fc`](https://github.com/getgems-io/nft-contracts#nft-fixprice-sale-v4r1fc):
виставлення NFT на продаж і покупку за **TON** або **жетони**. Працює **без API Getgems**: стан читається
напряму з блокчейну через публічний toncenter (get-методи + індексатор v3), а транзакції підписуються
гаманцем через TonConnect.

## Можливості

| Вкладка | Що робить |
|---|---|
| **NFT** | Мінт NFT за контрактом Getgems `nft-single.fc` (on-chain метадані TEP-64, роялті). Список ваших NFT. |
| **Жетони** | Створення демо-жетонів (dUSD 6 dec, GEM 9 dec, або свій): деплой jetton-minter + мінт емісії собі. Додавання будь-якого існуючого жетона за адресою. Баланси. |
| **Виставити** | Деплой контракту продажу: ціна в TON та/або в кількох жетонах, адреса маркетплейсу, комісія, роялті (підтягується з NFT). Режими `deploy_blank` і `deploy_jetton` (підписаний ed25519). Передача NFT на контракт в тій самій транзакції. |
| **Продажі** | Усі поля `get_fix_price_data_v4`, статус, рекомендовані перевірки (хеш коду, власник NFT, workchain, % комісій), і всі дії контракту (див. нижче). Можна додати будь-який v4r1 продаж за адресою. |
| **Журнал** | Історія надісланих транзакцій з посиланнями на tonviewer. |

Шапка: перемикач **testnet / mainnet**, кнопка **🚰 Тестові TON** (бот [@testgiver_ton_bot](https://t.me/testgiver_ton_bot)),
**підключення гаманця** (TonConnect), налаштування API-ключа toncenter (необов’язково; без нього ~1 запит/с).

### Покриття функціоналу контракту

| Функція контракту | Op | Хто | Де в UI |
|---|---|---|---|
| Деплой без жетонів | `0x664c0905` deploy_blank | будь-хто | Виставити → deploy_blank |
| Деплой з цінами в жетонах (підпис) | `0xfb5dbf47` deploy_jetton | marketplace з data | Виставити → deploy_jetton |
| Ініціалізація | `ownership_assigned` від NFT | NFT | «Одразу передати NFT» / Продажі → Передати NFT |
| Купівля за TON | `0` (порожнє тіло) або `2` buy | будь-хто | Продажі → Купити (вибір op) |
| Купівля за жетони | `transfer_notification` | jetton wallet продажу | Продажі → Купити за X |
| Повернення жетонів (не той жетон / мало / закрито) | — | контракт | автоматично |
| Скасування | `3` або коментар `"cancel"` | власник або маркетплейс | Продажі → Скасувати (вибір способу) |
| Зміна ціни (TON + словник жетонів) | `0xfd135f7b` change_price | nft_owner | Продажі → Змінити ціну |
| Аварійне повідомлення | `555` | маркетплейс, коли продаж завершено/не ініціалізовано | Продажі → op 555: забрати NFT, вивести TON, забрати жетони |
| Get-метод | `get_fix_price_data_v4` | — | Продажі → таблиця |

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # e2e-тести всіх повідомлень на справжньому коді контракту (@ton/sandbox)
npm run build      # статичний сайт у dist/
```

**TonConnect manifest.** Гаманець завантажує `tonconnect-manifest.json` з адреси застосунку, тож для мобільних
гаманців сайт має бути публічно доступним. Manifest генерується при збірці; публічну адресу передайте через
`APP_URL`:

```bash
APP_URL=https://example.com/nft-shop/ npm run build
```

У репозиторії є workflow `.github/workflows/pages.yml` — після мержу в `main` і ввімкнення
**Settings → Pages → Source: GitHub Actions** сайт буде на `https://<owner>.github.io/<repo>/`.

## Сценарій демонстрації (testnet)

1. Перемкніть гаманець (Tonkeeper тощо) на testnet, підключіть, візьміть TON у боті.
2. **Жетони** → створіть `dUSD` і `GEM`.
3. **NFT** → змінтіть NFT → «Виставити на продаж».
4. **Виставити** → ціна 1 TON, 10 dUSD, 50 GEM → «Створити продаж (deploy_jetton)».
5. **Продажі** → переконайтесь, що всі перевірки зелені. Змініть ціну, скасуйте, створіть знову.
6. З іншого гаманця (переведіть на нього трохи dUSD) купіть NFT за TON або за жетон.
7. Як маркетплейс виведіть залишок TON з завершеного контракту через op 555.

## Важливі нюанси (перевірено в тестах)

- **deploy_jetton**: ключ словника цін — хеш адреси jetton-гаманця *самого контракту продажу*, тому словник
  неможливо покласти в state init (адреса залежить від data). Контракт деплоїться з порожнім словником і
  одноразовим публічним ключем; словник і нова адреса маркетплейсу передаються в підписаному повідомленні, яке
  має надіслати адреса, що записана маркетплейсом у data.
- **Газ на жетони**: контракт додає до кожного свого переказу жетонів лише 0.04 TON. Референсний
  `jetton-wallet.fc` з `ton-blockchain/token-contract` вимагає більше (2×0.015 + 0.01 + fwd), тому
  у демо-жетоні `gas_consumption` зменшено до 0.01 TON (`contracts/jetton/jetton-wallet.fc`). Реальні сучасні
  жетони (USD₮ тощо) працюють з контрактом без змін.
- **Переплата жетонами**: «хвіст» повертається повідомленням з mode 64, якому може не вистачити TON на балансі
  контракту — тоді надлишок лишається на jetton-гаманці продажу. UI платить рівно ціну, а застряглі жетони
  маркетплейс забирає через op 555 (не раніше ніж через 10 хв після продажу — помилка 406).
- Якщо NFT прийшла на адресу продажу раніше за деплой, контракт лишається неініціалізованим — NFT повертає
  маркетплейс через op 555.

## Структура

```
contracts/getgems/   вихідники контрактів Getgems (довідково)
contracts/jetton/    вихідники демо-жетона (token-contract, ft/)
scripts/             компіляція жетона (func-js) і перевірка хешу коду продажу
src/contracts/       BOC коду контрактів
src/lib/contracts.ts побудова всіх повідомлень і state init
src/lib/toncenter.ts читання стану з блокчейну (toncenter v2/v3)
src/tabs/            вкладки UI
tests/sale.test.ts   e2e-сценарії в @ton/sandbox
```
